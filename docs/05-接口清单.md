# 05 · 接口清单（自建 REST + SSE）

## 1. 通用约定

| 项 | 约定 |
|---|---|
| 前缀 | `/api/v1` |
| 鉴权 | `Authorization: Bearer <JWT>`；JWT 内含 `sub`(user_id)、`tid`(tenant_id)、`role` |
| 响应体 | `{ "code": 0, "message": "ok", "data": …, "request_id": "uuid" }` |
| 分页 | 请求 `page`(默认1) / `page_size`(默认20，最大100)；响应 `data: { items, total, page, page_size }` |
| 时间 | ISO8601 带时区，如 `2026-03-01T10:20:30+08:00` |
| ID | UUID 字符串 |
| 幂等 | 上传以 `kb_id + sha256` 幂等；出题以 `Idempotency-Key` 头可选去重 |
| 权限 | 角色：`owner > admin > member`；KB 角色：`owner > editor > viewer` |

### 1.1 错误码

| code | HTTP | 含义 |
|---|---|---|
| 0 | 200 | 成功 |
| 40001 | 400 | 参数校验失败 |
| 40101 | 401 | 未登录 / Token 失效 |
| 40301 | 403 | 无该知识库权限 |
| 40401 | 404 | 资源不存在（含越权时统一返回此码） |
| 40901 | 409 | 冲突（同名 KB、重复上传） |
| 41301 | 413 | 文件超限 |
| 41501 | 415 | 文件类型不支持 |
| 42901 | 429 | 触发限流 / 配额 |
| 50001 | 500 | 服务内部错误 |
| 50201 | 502 | Dify 调用失败 |
| 50202 | 502 | MinerU 解析失败 |
| 50203 | 502 | 内容审核服务异常 |
| 50301 | 503 | 审核拦截（业务码，附 `audit_log_id`） |

## 4. 文档

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/kbs/{kb_id}/documents` | 上传（multipart，字段 `files[]`，支持多个；返回 `202`） |
| GET | `/kbs/{kb_id}/documents` | 列表：`status, keyword, page, page_size` |
| GET | `/documents/{document_id}` | 详情（含 `status, audit_status, dify_indexing_status`） |
| GET | `/documents/{document_id}/status` | 轻量轮询（前端 2s 一次）：`{status, stage_progress, error_code}` |
| GET | `/documents/{document_id}/preview` | 解析后 Markdown 预览（分页/截断） |
| GET | `/documents/{document_id}/chunks` | 分块查看（代理 Dify `segments` 接口） |
| POST | `/documents/{document_id}/retry` | 重新解析/入库（`stage` 可选） |
| DELETE | `/documents/{document_id}` | 删除（软删 + 删 Dify document） |

```jsonc
// POST /kbs/{kb_id}/documents 响应（202）data
{ "accepted": [ { "document_id": "doc_uuid", "task_id": "task_uuid",
                  "filename": "第3章.pdf", "status": "pending" } ],
  "rejected": [ { "filename": "a.exe", "code": 41501, "message": "不支持的文件类型" } ] }
```

**上传校验规则**（后端硬校验，不依赖前端）

| 项 | 规则 |
|---|---|
| 扩展名 | `pdf, doc, docx, ppt, pptx, md, png, jpg, jpeg` |
| 单文件大小 | ≤ 15MB（与 Dify `UPLOAD_FILE_SIZE_LIMIT` 对齐） |
| 单次数量 | ≤ 10（与 `UPLOAD_FILE_BATCH_LIMIT` 对齐） |
| 内容校验 | 读文件头判断真实类型，拒绝扩展名伪造 |
| 审核 | 图片 → 图片审核；文件名/文本 → 文本审核；命中即 `41501/50301` 拒绝 |

## 5. 问答（SSE 流式）

```
POST /kbs/{kb_id}/chat/stream
Content-Type: application/json
Accept: text/event-stream
```

```jsonc
// 请求
{ "query": "二叉树的遍历方式有哪些？",
  "conversation_id": "conv_uuid 或 null（新会话）",
  "top_k": 5,                 // 可空，默认取 KB 配置
  "score_threshold": 0.5,     // 可空
  "answer_style": "教学式，简洁分点" }   // 可空
```

### 5.1 SSE 事件表（后端 → 前端）

| event | data | 说明 |
|---|---|---|
| `meta` | `{conversation_id, message_id, kb_id}` | 首帧；新会话时 `conversation_id` 为后端新建 ID |
| `message` | `{delta: "二叉树"}` | 增量文本，前端追加渲染 |
| `sources` | `{items: [{index, document_id, document_name, segment_id, score, content}]}` | 引用来源；**在首个 `message` 之前发送**（检索先于生成） |
| `usage` | `{prompt_tokens, completion_tokens, total_tokens, latency_ms}` | 来自 `message_end.metadata.usage` |
| `moderation` | `{scene: "input"\|"output", flagged: true, message: "已被拦截"}` | 审核命中 |
| `error` | `{code, message}` | `50201` Dify 失败 / `50001` 内部错误 |
| `done` | `{message_id, conversation_id, sources_count}` | 正常结束 |

### 5.2 Dify `retriever_resources` → 本地 `sources` 映射

| Dify 字段 | 本地字段 | 备注 |
|---|---|---|
| `dataset_id` | `dataset_id` | Dify dataset |
| `document_id` | — | 仅用于后端反查 |
| `document_name` | `document_name` | 展示用 |
| `segment_id` | `segment_id` | 溯源主键 |
| `score` | `score` | 保留 4 位小数 |
| `content` | `content` | 前端折叠展示，截断 300 字 |
| `position` | `segment_position` | 段落序号 |
| （无） | `document_id`（本地） | 后端用 `document.dify_document_id` 反查补齐 |

> 引用编号规则：`sources[0]` 对应答案中的 `[1]`，以此类推；后端在 `sources` 事件中已按 `retriever_resources` 顺序编号为 `index: 1..n`。

### 5.3 关键实现要求

- 后端使用 **Dify `/chat-messages` + `response_mode: "streaming"`**，逐行解析 `data: {...}`，把 `message` 事件转为本地 `message`。**不缓冲整段**，确保首字延迟。
- 客户端断开（`asyncio.CancelledError` / 连接重置）时，后端应把已生成内容落库并结束会话，标记 `finish_reason=client_abort`。
- 全流程写 `usage_record`（scene=`chat`），并更新 `conversation.message_count / last_message_at`。
- Nginx 必须 `proxy_buffering off; proxy_read_timeout 300s;`，否则流式被缓冲。

```txt
// 响应示例（text/event-stream）
event: meta
data: {"conversation_id":"c1","message_id":"m1","kb_id":"kb1"}

event: sources
data: {"items":[{"index":1,"document_id":"d1","document_name":"第3章.pdf","segment_id":"s12","score":0.8342,"content":"..."}]}

event: message
data: {"delta":"二叉树主要有"}

event: message
data: {"delta":"四种遍历方式…[1]"}

event: usage
data: {"prompt_tokens":812,"completion_tokens":156,"total_tokens":968,"latency_ms":2140}

event: done
data: {"message_id":"m1","conversation_id":"c1","sources_count":2}
```

## 6. 对话历史

| 方法 | 路径 | 说明 | 参数 |
|---|---|---|---|
| GET | `/conversations` | 会话列表 | `kb_id?, keyword?, page, page_size` |
| GET | `/conversations/{conversation_id}` | 会话详情（含 `dify_conversation_id` 是否有效） | — |
| GET | `/conversations/{conversation_id}/messages` | 消息列表（含 `sources`） | `page, page_size`（默认倒序分页后再正序渲染） |
| PATCH | `/conversations/{conversation_id}` | 重命名 | `{title}` |
| DELETE | `/conversations/{conversation_id}` | 删除（先删 Dify 会话再软删本地） | — |
| POST | `/conversations/{conversation_id}/continue` | 续聊（= `/chat/stream` 带该 `conversation_id`） | 同 §5 请求体 |

```jsonc
// GET /conversations 响应 data
{ "items": [ { "id": "c1", "title": "二叉树遍历方式有哪些？", "kb_id": "kb1",
               "kb_name": "数据结构与算法", "message_count": 8,
               "last_message_at": "2026-03-01T10:20:30+08:00" } ],
  "total": 12, "page": 1, "page_size": 20 }
```

> Dify 侧会话失联（用户在 Dify 控制台删除等）时：`GET /conversations/{id}` 返回 `dify_available: false`，前端隐藏"继续追问"按钮，历史仍可读（本地 `message` 已归档）。

## 7. 智能出题

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/quizzes` | 生成题目（同步等待 Dify Workflow，超时 120s） |
| GET | `/quizzes` | 我的出题记录：`kb_id?, page, page_size` |
| GET | `/quizzes/{quiz_id}` | 详情（`include_answer` 控制是否返答案与解析） |
| POST | `/quizzes/{quiz_id}/answers` | 批量提交作答并判分 |
| GET | `/quizzes/{quiz_id}/result` | 成绩单（得分、对错、错题列表） |
| DELETE | `/quizzes/{quiz_id}` | 删除（软删） |

```jsonc
// POST /quizzes 请求
{ "kb_id": "kb1",
  "types": ["single", "multi", "judge", "short"],
  "count": 10,                    // 1-30
  "difficulty": "medium",         // easy | medium | hard | mixed
  "topic": "二叉树的遍历" }        // 可空，空则覆盖 KB 核心知识点
```

```jsonc
// POST /quizzes 响应（201）data
{ "quiz_id": "q1", "status": "ready", "question_count": 10,
  "questions": [
    { "id": "qu1", "seq": 1, "type": "single", "difficulty": "easy",
      "stem": "二叉树的中序遍历顺序是？",
      "options": [ {"key":"A","text":"根-左-右"}, {"key":"B","text":"左-根-右"},
                   {"key":"C","text":"左-右-根"}, {"key":"D","text":"右-根-左"} ],
      "answer": "B", "analysis": "中序遍历先访问左子树…",
      "sources": [ {"index":1, "document_id":"d1", "document_name":"第3章.pdf",
                    "segment_id":"s12", "score":0.83, "content":"…"} ] }
  ] }
```

```jsonc
// POST /quizzes/{quiz_id}/answers 请求
[ { "question_id": "qu1", "answer": "B" },
  { "question_id": "qu4", "answer": ["A", "C"] },
  { "question_id": "qu7", "answer": true },
  { "question_id": "qu10", "answer": "二叉树遍历是指按某种顺序访问每个节点一次" } ]

// 响应 data
{ "total": 10, "correct": 7, "score": 72.5,
  "items": [
    { "question_id": "qu1", "is_correct": true, "correct_answer": "B" },
    { "question_id": "qu10", "is_correct": false, "score": 55,
      "correct_answer": "…参考答案…",
      "feedback": "命中要点：遍历定义；遗漏：三种基本顺序的区分",
      "analysis": "…" }
  ],
  "wrong_question_ids": ["qu10", "…"] }
```

**入参校验**

| 字段 | 规则 |
|---|---|
| `count` | 1–30；实际题数可能略少（模型输出不合规被剔除），响应以 `question_count` 为准 |
| `types` | 至少 1 项，取值 `single/multi/judge/short` |
| `difficulty` | `easy/medium/hard/mixed` |
| 缓存 | 相同 `(kb_id, types, count, difficulty, topic, 检索块 hash)` 30 分钟内命中缓存，直接复用（省 token） |

## 10. 后端 → Dify 的调用对照表（供实现参考）

| 本地能力 | Dify 接口 | 备注 |
|---|---|---|
| 建知识库 | `POST /v1/datasets` | 创建后写回 `kb.dify_dataset_id` |
| 删知识库 | `DELETE /v1/datasets/{dataset_id}` | 异步；失败进任务表重试 |
| 文档入库 | `POST /v1/datasets/{id}/document/create-by-text` | 走审核 + MinerU 后的 Markdown |
| 文件入库（PDF 等） | `POST /v1/datasets/{id}/document/create-by-file` | 直传原文件（走 Dify 自带提取器 / 流水线解析分支）：`DIFY_PARSE_EXTENSIONS` 命中的扩展名走这条，见 docs/04 §1.2 |
| 入库进度 | `GET /v1/datasets/{id}/documents/{document_id}/indexing-status` | 轮询至 `completed` |
| 文档列表/删除 | `GET /v1/datasets/{id}/documents` · `DELETE .../documents/{document_id}` | 同步状态与删除 |
| 分块查看 | `GET /v1/datasets/{id}/documents/{document_id}/segments` | 文档详情页"分块"标签 |
| 问答 | `POST /v1/chat-messages`（`response_mode=streaming`） | SSE 代理核心 |
| 历史消息 | `GET /v1/messages?conversation_id=` | 校验/补偿归档 |
| 会话管理 | `GET /v1/conversations?user=` · `DELETE /v1/conversations/{id}` | 删会话需先调此接口 |
| 出题 / 判分 | `POST /v1/workflows/run` | `response_mode=blocking`，超时 120s |
| 文件上传（备用） | `POST /v1/files/upload` | 供需要 file 变量的场景 |

> **所有 Dify 调用都由后端发起**，API Key 只存在于后端 `.env`；前端零 Dify 凭据。所有调用记录 `request_id` 与耗时，失败统一映射为 `50201`。
