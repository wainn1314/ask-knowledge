# 01 · 架构总览

## 1. 组件清单与版本

| 组件 | 版本 / 选型 | 部署方式 | 说明 |
|---|---|---|---|
| Dify | **1.17.0**（建议尽快 1.17.1） | Docker Compose | RAG + LLM 编排；知识管道、Chatflow、Workflow、Moderation 扩展 |
| Dify 插件 | `langgenius/mineru`（v0.5.8）、`Alibaba Cloud AI Guardrails`(可选) | Dify 插件市场安装 | MinerU 支持 PDF/DOC/DOCX/PPT/PPTX/PNG/JPG/JPEG |
| MinerU 服务 | 本地部署（web_api）或 官方 API | 独立进程 / 云 | 由后端调用，作为"解析器"，输出 Markdown + JSON |
| 业务后端 | Python 3.11 + FastAPI + SQLAlchemy 2.0 + Alembic | uvicorn / gunicorn | 全部业务逻辑与 Dify 适配 |
| 业务库 | PostgreSQL 16 | 单实例 / 云 RDS | 多租户行级隔离 |
| 前端 | Vue 3 + TypeScript + Vite + Element Plus + Pinia | 静态托管 | 自建全部界面（不使用 Dify 前端） |
| 文件存储 | 本地磁盘（MVP）→ 阿里云 OSS（预留） | — | 存原始文件，便于重新解析 |
| 内容安全 | 阿里云内容安全（文本/图片审核） | 云 API | 由后端与 moderation 适配服务调用 |
| 反向代理 | Nginx | 云主机 | HTTPS、SSE 需关闭缓冲（`proxy_buffering off`） |

### 1.1 Dify 关键环境变量（必须核对）

| 变量 | 值 | 为什么 |
|---|---|---|
| `FILES_URL` | 指向 Dify API 可达地址（容器部署用 `http://api:5001`，本机用局域网 IP） | **MinerU 插件处理文件上传的必需项**，不配会报文件访问错误 |
| `UPLOAD_FILE_BATCH_LIMIT` | 默认 5，MVP 建议 10 | 单次批量上传数量 |
| `UPLOAD_FILE_SIZE_LIMIT` | 默认 15（MB） | 单文件大小 |
| `ATTACHMENT_IMAGE_FILE_SIZE_LIMIT` | 默认 2（MB） | 图片作为 chunk 附件的提取上限 |
| `SINGLE_CHUNK_ATTACHMENT_LIMIT` | 默认 10 | 每个 chunk 最多附件数 |
| `INVITE_EXPIRY_HOURS` | — | Dify 成员邀请有效期（我们不用其成员体系，仅备查） |
| `CONSOLE_WEB_URL` | 可达地址 | 邀请链接构建（仅备查） |

> 修改后需 `docker compose up -d` 重启 Dify 生效。

## 2. 系统分层与职责边界

```
Controller/Router → Service → Repository → PostgreSQL
                        │
                        └→ Integration（Dify / MinerU / 阿里云审核 / 存储）
```

| 能力 | Dify 负责 | 自建后端负责 |
|---|---|---|
| 文档解析与分块 | 分块、嵌入、向量入库、检索 | 上传接收、格式校验、内容审核、调用 MinerU、调 Dataset API 入库、状态机与重试 |
| 知识库 | Dataset 的创建/删除/检索配置 | 租户归属、成员权限、可见性、Dify dataset_id 映射 |
| 问答 | 检索 → Prompt → LLM → 流式输出 → 引用 | 鉴权、KB 范围选择、SSE 透传、引用映射、归档、用量统计 |
| 出题 | 检索 + 结构化生成 | 参数校验、落库、作答判分、错题本 |
| 对话历史 | 存 conversation/message（用于续聊） | 归档与检索（按租户/用户/KB）、删除与回溯 |
| 内容审核 | 输入/输出扩展点触发（含流式 100 字符分段） | 文档导入审核、审核适配层、审核日志、人工复核标记 |

## 4. 四条核心链路

### 4.1 上传 → 可问答（异步）

```
前端 POST /api/v1/kb/{kb_id}/documents（multipart）
  → 后端：格式白名单校验 + 大小校验（pdf/docx/pptx/md/png|jpg|jpeg）
  → 存原始文件：data/uploads/{tenant_id}/{kb_id}/{doc_id}{ext}
  → 建 document 记录（status=pending）
  → 审核：阿里云 文本审核（文件名）+ 图片审核（图片文件）
  → 入任务表（task_type=parse）
  → 立即返回 202 { document_id, task_id }
后台 worker：
  parse：调 MinerU → Markdown（+ 图片资源）
  audit_parse：对解析文本分片送审（命中则整篇 blocked）
  index：调 Dify  POST /datasets/{dataset_id}/document/create-by-text
          （segmentation: {separator:"\n\n", max_tokens:512, chunk_overlap:50}）
          或 create-by-file 上传 Markdown
  → 记录 dify_document_id → 轮询/回调 indexing_status=completed → status=ready
前端 GET /api/v1/documents/{id}/status（或 SSE）看进度
```

**关键约束**
- 任一步失败：`status=failed` + `error_code/message`，支持"重新解析"（复用原文件，不产生半成品）。
- 文件级幂等：`sha256` 去重，同 KB 内重复文件直接复用既有文档。
- 审核不过：`audit_status=blocked`，文档不入库，保留审核日志。

### 4.2 问答（流式 + 引用）

```
前端 POST /api/v1/kb/{kb_id}/chat/stream   （SSE）
  → 后端鉴权 + 校验 KB 访问权限
  → 可选：调 Dify moderation 已覆盖输入审核（由 Dify 侧配置）
  → 调 Dify POST /chat-messages { response_mode:"streaming",
        query, conversation_id?, user: f"{tenant_id}:{user_id}",
        inputs:{ kb_ids:[...], top_k } }
  → 透传事件：message(delta) / message_end(retriever_resources, usage)
  → 后端把 retriever_resources 映射为 sources（document_id/segment_id/score/content）
    并落 message 表 → 结束发送 done 事件
```

### 4.3 出题 → 作答 → 错题本

```
POST /api/v1/quizzes            （kb_id, types[], count, difficulty, topic?）
  → 后端调 Dify Workflow /workflows/run（inputs 同上）→ 结构化题目 JSON
  → 校验（题型/选项数/答案合法）→ 落 quiz + question（含 source_segment_ids）
POST /api/v1/quizzes/{id}/answers   [{question_id, answer}]
  → 客观题规则判分；简答题调 Dify 评分工作流（LLM + 评分要点）
  → 写 answer_record；答错 → upsert wrong_book(wrong_count+1, status=unmastered)
PATCH /api/v1/wrong-book/{id}     { status: mastered | reviewing }
DELETE /api/v1/wrong-book/{id}    （软删除，不动 question）
```

### 4.4 内容审核（4 个卡点）

| 卡点 | 触发方 | 实现 |
|---|---|---|
| ① 文件上传 | 后端 | 文本（文件名/文本类内容）+ 图片审核；命中 → 拒绝入库 |
| ② 解析文本入库前 | 后端 worker | 分片送审（按 1000 字滑动），命中 → 文档 blocked |
| ③ 用户提问 | Dify | `app.moderation.input` 扩展点 → 适配服务 → 阿里云 |
| ④ 模型输出 | Dify | `app.moderation.output` 扩展点（**流式自动 100 字符分段**）→ 适配服务 → 阿里云 |

> 适配服务同时实现 `point=ping` → `{"result":"pong"}` 供 Dify 配置校验；`flagged=true` 时可返回 `action=direct_output` + `preset_response` 直接拦截。

## 5. 非功能要求

| 维度 | 指标 / 做法 |
|---|---|
| 解析并发 | worker 并发 2（CPU 版 MinerU 是瓶颈），队列按租户公平调度 |
| 问答首字延迟 | ≤ 3s（TopK=5，Rerank 开启时 ≤ 5s） |
| 检索准确率 | TopK 默认 5、Score 阈值 0.5、开启 Rerank；提供"检索测试"页面 |
| 幂等与重试 | 任务表 + 最大重试 3 次 + 指数退避；Dify 调用超时 60s（解析类 10min） |
| 可观测 | 每个请求：request_id / tenant_id / 耗时 / token / 错误码；任务表可查进度 |
| 成本控制 | 文档 sha256 去重避免重复嵌入；出题结果按 `(kb_id, types, count, difficulty, chunk_hash)` 缓存 |
| 安全 | Dify API Key 仅存后端；上传目录不可直接 Web 访问；JWT + 租户过滤器强制注入 |
