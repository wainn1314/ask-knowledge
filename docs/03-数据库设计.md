# 03 · 数据库设计（PostgreSQL 16）

## 1. 设计原则

1. **多租户行级隔离**：所有业务表强制带 `tenant_id`，由 Repository 层统一注入过滤条件，禁止业务代码手写查询时遗漏。
2. **不建物理外键**：靠应用层保证引用完整性，便于后续分库/归档与批量删除；关键关联建普通索引。
3. **软删除**：`is_deleted BOOLEAN + deleted_at TIMESTAMPTZ`，唯一约束用**部分唯一索引**（`WHERE is_deleted = FALSE`）保证"删后可重建同名"。
4. **Dify 映射字段**：`dify_dataset_id / dify_document_id / dify_conversation_id / dify_message_id` 全部允许 NULL，Dify 侧对象一旦失联不影响本地数据可用性。
5. **chunk 不入本地库**：chunk 权威在 Dify，引用通过 `message.sources` / `question.source_segments` 存快照。

## 2. 租户与用户

```sql
-- 租户（对应"组织/客户"；MVP 只有一个，但字段从 Day 1 就建好）
CREATE TABLE tenant (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        VARCHAR(128) NOT NULL,
    code        VARCHAR(64)  NOT NULL,                       -- 租户短码，用于 user 标识前缀
    status      SMALLINT     NOT NULL DEFAULT 1,             -- 1 启用 / 0 停用
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uk_tenant_code ON tenant(code);

-- 用户
CREATE TABLE app_user (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id     UUID         NOT NULL,
    email         VARCHAR(255) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    nickname      VARCHAR(64),
    role          VARCHAR(16)  NOT NULL DEFAULT 'member',    -- owner / admin / member
    status        SMALLINT     NOT NULL DEFAULT 1,
    last_login_at TIMESTAMPTZ,
    created_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uk_user_tenant_email ON app_user(tenant_id, lower(email));
CREATE INDEX idx_user_tenant ON app_user(tenant_id);
```

## 3. 知识库与权限

```sql
CREATE TABLE kb (
    id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id         UUID         NOT NULL,
    name              VARCHAR(128) NOT NULL,
    description       TEXT,
    icon              VARCHAR(255),
    owner_id          UUID         NOT NULL,
    visibility        VARCHAR(16)  NOT NULL DEFAULT 'private', -- private | tenant
    -- Dify 映射
    dify_dataset_id   VARCHAR(64),
    embedding_model   VARCHAR(128),
    -- 检索与分块配置（默认值来自 .env，可被 KB 覆盖）
    chunk_size        INT          NOT NULL DEFAULT 512,       -- 注意：Dify 侧单位是「字符」
    chunk_overlap     INT          NOT NULL DEFAULT 50,
    top_k             INT          NOT NULL DEFAULT 5,
    score_threshold   NUMERIC(4,3) NOT NULL DEFAULT 0.500,
    retrieval_mode    VARCHAR(16)  NOT NULL DEFAULT 'hybrid',  -- semantic | full_text | hybrid
    rerank_enabled    BOOLEAN      NOT NULL DEFAULT TRUE,
    semantic_weight   NUMERIC(4,3) NOT NULL DEFAULT 0.700,
    doc_count         INT          NOT NULL DEFAULT 0,         -- 冗余计数，列表页展示
    -- 状态
    status            SMALLINT     NOT NULL DEFAULT 1,         -- 1 正常 / 2 删除中 / 0 已删除
    is_deleted        BOOLEAN      NOT NULL DEFAULT FALSE,
    created_at        TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at        TIMESTAMPTZ  NOT NULL DEFAULT now(),
    deleted_at        TIMESTAMPTZ
);
CREATE UNIQUE INDEX uk_kb_tenant_name ON kb(tenant_id, lower(name)) WHERE is_deleted = FALSE;
CREATE INDEX idx_kb_tenant ON kb(tenant_id, created_at DESC) WHERE is_deleted = FALSE;

-- 知识库成员与权限：owner(管理+授权) / editor(上传+问答) / viewer(仅问答)
CREATE TABLE kb_member (
    id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id  UUID        NOT NULL,
    kb_id      UUID        NOT NULL,
    user_id    UUID        NOT NULL,
    role       VARCHAR(16) NOT NULL,                           -- owner | editor | viewer
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uk_kb_member ON kb_member(kb_id, user_id);
CREATE INDEX idx_kb_member_user ON kb_member(tenant_id, user_id);
```

## 4. 文档与异步任务

```sql
CREATE TABLE document (
    id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id             UUID          NOT NULL,
    kb_id                 UUID          NOT NULL,
    uploader_id           UUID          NOT NULL,
    filename              VARCHAR(512)  NOT NULL,
    file_ext              VARCHAR(16)   NOT NULL,              -- pdf / docx / pptx / md / png ...
    file_size             BIGINT        NOT NULL,
    sha256                CHAR(64)      NOT NULL,
    storage_path          VARCHAR(1024) NOT NULL,              -- 原始文件路径（用于重新解析）
    parsed_path           VARCHAR(1024),                       -- MinerU 产出 Markdown 路径
    page_count            INT,
    chunk_count           INT,
    -- 状态机：pending → parsing → auditing → indexing → ready
    --                                        ↘ failed / blocked
    status                VARCHAR(16)   NOT NULL DEFAULT 'pending',
    stage_progress        SMALLINT      NOT NULL DEFAULT 0,    -- 0-100
    error_code            VARCHAR(64),
    error_message         TEXT,
    audit_status          VARCHAR(16)   NOT NULL DEFAULT 'pending', -- pending|pass|block|review
    parse_mode            VARCHAR(16),                         -- mineru_local | mineru_api | builtin
    parse_duration_ms     INT,
    dify_document_id      VARCHAR(64),
    dify_indexing_status  VARCHAR(16),                         -- waiting|parsing|cleaning|splitting|indexing|completed|error
    retry_count           SMALLINT      NOT NULL DEFAULT 0,
    is_deleted            BOOLEAN       NOT NULL DEFAULT FALSE,
    created_at            TIMESTAMPTZ   NOT NULL DEFAULT now(),
    updated_at            TIMESTAMPTZ   NOT NULL DEFAULT now(),
    deleted_at            TIMESTAMPTZ
);
CREATE UNIQUE INDEX uk_document_kb_sha ON document(kb_id, sha256) WHERE is_deleted = FALSE;
CREATE INDEX idx_document_kb ON document(tenant_id, kb_id, created_at DESC) WHERE is_deleted = FALSE;
CREATE INDEX idx_document_status ON document(tenant_id, status) WHERE is_deleted = FALSE;

-- 异步任务表（解析 / 审核 / 入库 / 删除索引）：worker 轮询 + 重试
CREATE TABLE parse_task (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id     UUID        NOT NULL,
    document_id   UUID        NOT NULL,
    task_type     VARCHAR(16) NOT NULL DEFAULT 'parse',        -- parse | reparse | delete_index
    stage         VARCHAR(24),                                 -- parse | audit | index
    status        VARCHAR(16) NOT NULL DEFAULT 'queued',       -- queued|running|success|failed|dead
    priority      SMALLINT    NOT NULL DEFAULT 100,
    attempt       SMALLINT    NOT NULL DEFAULT 0,
    max_attempt   SMALLINT    NOT NULL DEFAULT 3,
    locked_by     VARCHAR(64),
    locked_at     TIMESTAMPTZ,
    next_run_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    error_message TEXT,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    finished_at   TIMESTAMPTZ
);
CREATE INDEX idx_task_pick ON parse_task(next_run_at, priority) WHERE status IN ('queued', 'failed');
CREATE INDEX idx_task_document ON parse_task(document_id);
```

> worker 取任务用 `SELECT ... FOR UPDATE SKIP LOCKED LIMIT 1`，多进程安全。

## 5. 出题 / 作答 / 错题本

```sql
CREATE TABLE quiz (
    id                   UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id            UUID        NOT NULL,
    kb_id                UUID        NOT NULL,
    creator_id           UUID        NOT NULL,
    title                VARCHAR(255),
    config               JSONB       NOT NULL,   -- {types:[...],count:10,difficulty:"medium",topic:""}
    question_count       INT         NOT NULL DEFAULT 0,       -- 实际生成题数
    dify_workflow_run_id VARCHAR(64),
    status               VARCHAR(16) NOT NULL DEFAULT 'generating', -- generating|ready|failed
    error_message        TEXT,
    is_deleted           BOOLEAN     NOT NULL DEFAULT FALSE,
    created_at           TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at           TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_quiz_kb ON quiz(tenant_id, kb_id, created_at DESC) WHERE is_deleted = FALSE;

CREATE TABLE question (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID        NOT NULL,
    quiz_id         UUID        NOT NULL,
    kb_id           UUID        NOT NULL,
    seq             INT         NOT NULL,
    type            VARCHAR(16) NOT NULL,      -- single | multi | judge | short
    stem            TEXT        NOT NULL,
    options         JSONB,                     -- [{"key":"A","text":"..."}]；判断题/简答题为 null
    answer          JSONB       NOT NULL,      -- single:"A" multi:["A","C"] judge:true short:"参考答案"
    analysis        TEXT,                      -- 答案解析
    difficulty      VARCHAR(16) NOT NULL DEFAULT 'medium',  -- easy | medium | hard
    grading_points  JSONB,                     -- 简答题评分要点 ["关键词1","关键词2"]
    source_segments JSONB,                     -- 引用快照（见下）
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_question_quiz ON question(quiz_id, seq);
CREATE INDEX idx_question_kb ON question(tenant_id, kb_id);

-- source_segments 结构（题目溯源，与 message.sources 同构）
-- [{"dataset_id":"","document_id":"","document_name":"第3章.pdf",
--   "segment_id":"","segment_position":12,"score":0.83,"content":"…原文片段…"}]

CREATE TABLE answer_record (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id   UUID         NOT NULL,
    user_id     UUID         NOT NULL,
    quiz_id     UUID         NOT NULL,
    question_id UUID         NOT NULL,
    user_answer JSONB,
    is_correct  BOOLEAN,                       -- 简答题按 score >= 60 判定
    score       NUMERIC(5,2),                  -- 0-100，仅简答题
    feedback    TEXT,                          -- 简答题评语 / 命中要点
    cost_ms     INT,
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_answer_user ON answer_record(tenant_id, user_id, created_at DESC);
CREATE INDEX idx_answer_question ON answer_record(question_id);

CREATE TABLE wrong_book (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id     UUID        NOT NULL,
    user_id       UUID        NOT NULL,
    kb_id         UUID        NOT NULL,
    question_id   UUID        NOT NULL,
    wrong_count   INT         NOT NULL DEFAULT 1,
    last_wrong_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    status        VARCHAR(16) NOT NULL DEFAULT 'unmastered',   -- unmastered | reviewing | mastered
    mastered_at   TIMESTAMPTZ,
    remark        TEXT,
    is_deleted    BOOLEAN     NOT NULL DEFAULT FALSE,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uk_wrong_user_question ON wrong_book(user_id, question_id) WHERE is_deleted = FALSE;
CREATE INDEX idx_wrong_user_status ON wrong_book(tenant_id, user_id, status) WHERE is_deleted = FALSE;
```

**业务规则**
- 答错：`INSERT ... ON CONFLICT (user_id, question_id) DO UPDATE SET wrong_count = wrong_book.wrong_count + 1, status = 'unmastered'`。
- 标记掌握：`status='mastered' + mastered_at=now()`；同题再次答错自动回落 `unmastered`。
- 删除错题：软删除；`question` 与 `answer_record` 保留（可回溯作答历史）。

```sql
    WHERE dify_conversation_id IS NOT NULL;

CREATE TABLE message (
    id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id         UUID        NOT NULL,
    conversation_id   UUID        NOT NULL,
    dify_message_id   VARCHAR(64),
    role              VARCHAR(16) NOT NULL,                    -- user | assistant
    content           TEXT        NOT NULL,
    sources           JSONB,                                   -- 引用来源快照（retriever_resources 归一化）
    audit_status      VARCHAR(16) NOT NULL DEFAULT 'pass',      -- pass | block | review
    prompt_tokens     INT,
    completion_tokens INT,
    latency_ms        INT,
    created_at        TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_message_conv ON message(conversation_id, created_at);
CREATE INDEX idx_message_dify ON message(dify_message_id);
```

> 归档策略：Dify 侧仍是**续聊真相源**（`conversation_id` 不可丢）；本地 `message` 表用于"按内容搜索历史 / 统计 / 审核回溯"。删除会话时先调 Dify `DELETE /conversations/{id}`，再软删本地记录。

## 8. 多租户隔离落地规则（务必遵守）

1. **强制注入**：所有 Repository 方法签名必须含 `tenant_id`，SQL 必带 `WHERE tenant_id = :tenant_id`；代码评审把"缺 tenant_id"视为阻断级问题。
2. **越权二次校验**：访问具体资源（KB / 文档 / 会话 / 错题）时，除 `tenant_id` 外还要校验资源归属，返回 404（而非 403）避免资源探测。
3. **Dify 侧隔离**：不为每个租户建 workspace/dataset 组的"一租户一空间"模式；每租户的知识库对应独立 dataset，`dify_dataset_id` 与 `kb` 一对一，后端在调用检索/问答时只传本租户已授权的 dataset_ids。
4. **用户标识**：传给 Dify 的 `user` 用 `"{tenant_code}:{user_id}"`，避免不同租户 user_id 在 Dify 侧串号。
5. **租户级软删**：删租户 = 逻辑停用（`tenant.status=0`）+ 各表按 `tenant_id` 软删 + 异步清理 Dify dataset，**不做物理 DELETE**（保留审计可追溯）。

## 9. 关系概览（逻辑 ER）

```
tenant 1─n app_user
tenant 1─n kb 1─n kb_member ─n app_user
kb     1─n document 1─n parse_task
kb     1─n quiz 1─n question
question 1─n answer_record ─n app_user
question 1─n wrong_book ─n app_user
kb     1─n conversation 1─n message
（audit_log / usage_record 通过 tenant_id 与各实体弱关联）
```

## 10. 迁移与初始化建议

- Alembic：`alembic revision --autogenerate`；**DDL 中每个部分唯一索引需手写**（autogenerate 对 `WHERE` 条件支持有限，生成后逐条比对本文档）。
- 种子数据：1 个 `tenant`（code=`default`）、1 个 owner 账号、1 个示例 KB。
- 环境：开发用 Docker Compose 起 PostgreSQL 16；生产用云 RDS + 每日逻辑备份。
- 大表增长点：`message`、`audit_log`、`usage_record` —— 预留按月分区/归档策略（MVP 先建索引，量级超 500 万行再分区）。
- 索引使用提醒：`parse_task` 的部分索引条件为 `status IN ('queued','failed')`，worker 恢复失败任务时依赖 `next_run_at` 排序。
